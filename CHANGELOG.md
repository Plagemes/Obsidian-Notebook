# Changelog

## Unreleased

### Fixed
- **Hidden ink is safe from scribble erase and pen gestures.** Scratching out visible writing (scribble erase or the delete gesture) no longer deletes the invisible-ink solutions under it, and hidden ink no longer counts for the delete or circle-select gestures, unless the solutions of that page are shown. Insert space still moves hidden ink with the rest of the page so that solutions stay next to their exercise.
- **Deleting a box or a marker no longer offers to delete the ink it frames.** Structured boxes and region markers do not own ink (they annotate a region, the ink is not written on them), so moving or deleting one leaves that ink alone; the offer after deleting a text box or an image never counts or deletes hidden ink while the solutions are not shown.
- **Marker labels changed on read are reported.** A marker label or box title that reading has to normalise (extra spaces, line breaks, too long, blank) now counts as a dropped detail, so the notice about repaired details appears instead of the label changing silently.
- **Error notices are never held back while writing.** Failed saves, backups of unreadable or conflicting files, integrity problems and a failed save before a version restore are shown at once instead of waiting until the pen is lifted.
- **Update links: Markdown links to notebooks with parentheses, and conflicted copies.** A relocated Markdown link now encodes `(`, `)`, `#` and `?` (a link to `Physics (1).notebook` no longer breaks), the text it replaces is taken exactly as written in the note, and a link is never moved to a sync conflicted copy (`Notes (1).notebook` next to `Notes.notebook`), which holds the same page ids.
- **Update links: fewer false links, and the line in the list.** Links inside fenced code in blockquotes, callouts and lists, inside `%% %%` comments and in the frontmatter are left alone, and the list shows the text of the line each link is on.
- **Moved pages keep their ids.** *Move to notebook…* keeps each page's id, so stable links (`#p3&id=…`) can follow the page with *Update links to notebook pages*. Only a page whose id the target already has gets a new one; that old → new pair is recorded in `<notebooks folder>/_meta/page-moves-<device>.json` (one file per device) and *Update links* uses it.
- **An empty sidecar file is never read as "no data".** An existing empty Inbox, practice or textbooks file (a sync app that has not finished downloading it, or a write cut short) is now treated as not ready: the change is refused with a notice saying so, a copy is kept, and the file is not written over.
- **Practice links and textbooks: one file per device.** `practice.json` and `textbooks.json` were shared by all devices, so the last device to write won and sync conflict copies were never read. Each device now writes only `_meta/practice-<device>.json` and `_meta/textbooks-<device>.json`, and every device's files are merged on read (attempt times add up across devices; for a textbook the latest setting or removal wins). The old shared files are still read, never written or deleted, so no record is lost.

## 0.7.0 — 2026-10-30

Not yet verified on Android hardware. The manual steps added in this version are numbered 135 to 177 in `docs/testing.md`; the ones that belong to each area are named below.

### Upgrade notes
- **New interface.** The long "…" menu and the page menu are replaced by the **All actions** sheet and the **page sheet**. Command ids are unchanged, so hotkeys keep working.
- **Library index version 4** (0.6 used version 3). The index is a cache in the plugin folder: it is rebuilt once on the first start of 0.7 (it now also keeps bookmark titles). The index of a newer plugin version is ignored and left as it is instead of being overwritten.
- **Presence files** (open on another device) are written to `<notebooks folder>/_meta/presence/`, one file per notebook and device; each device writes only its own files.
- **Per-device local data** is kept in Obsidian's local storage and never synced: the use counts behind the toolbar's quick actions and the *Recent* section, the log of recently edited pages, the safe-mode "opening" marker, the integrity ledger of written versions, and the device id and name.
- No change to the document format (still v7), the writing engine or saving.

### Added

  - **Toolbar**: tools in the first row; undo/redo, the current pen (opens the tool options), the favourite pens, up to six **quick actions** (ranked by priority and by your own use on this device), the page indicator and the save state in the second; one row on wide views.
  - **Contextual bar** at the bottom of the page: the selection's actions (copy, cut, duplicate, paste, white → transparent, save as stamp, delete, colour and width), paste for the lasso, the PDF page's actions (search, hide annotations, dim, margins, side by side), the side-by-side pane's actions, and the lecture actions while a class of the timetable is on. It can be collapsed.
  - **All actions** sheet (⊞: grouped sections with search and a *Recent* section) and the **page sheet** (tap the page indicator or a thumbnail's menu) with paper and size as chips. On a phone they are bottom sheets. The page sheet starts with a **Go to** section: *Go to page number…*, *Recently edited pages*, *One page at a time*.
  - **Radial dial** at the pen tip, redesigned: undo/redo, a width bubble, a colour bubble, the active tool drawn as a pen, and favourites · pen case · shapes. The colour ring has 12 colours, a custom colour and an eyedropper; the width bubble opens an arc slider; the pen case shows the tools with a stroke preview and "+" to save a favourite.
  - The status banners (safe mode, storage full, integrity, open on another device) and the heavy-page bar are part of the registry too, with their buttons.
  - New command *Tool: space*.
  - A visual system built on Obsidian's CSS variables (surfaces, elevation, radii, spacing, motion with *reduced motion* respected) applied to bars, popovers, sheets, panels, dialogs and the library.
  - Not yet verified on Android hardware.
- **Sync safety** (roadmap 342-345; steps 170-177). For vaults synced with Google Drive or OneDrive through a folder-sync app.
  - **Open on another device** (342): while a notebook is open, a small file `<notebooks folder>/_meta/presence/<notebook id>.<device id>.json` is refreshed every 5 minutes while the app is in the foreground (on resume only when it is that old) and removed on close. Opening a notebook that another device has open (seen in the last 15 minutes) shows a banner with **Open read-only** or **Open anyway**; it never blocks. Each device writes only its own files, so they cannot cause conflicted copies. Device id and name are stored on the device only; the name can be changed in *Settings, Device name*.
  - **Assets waiting for sync** (343): an image or PDF referenced by a page but not (completely) downloaded yet shows a "Waiting for sync" placeholder instead of an error, the page stays editable, and the file appears by itself when it arrives.
  - **Online-only notebooks** (344): a 0-byte (or NUL-filled) notebook file shows **Not downloaded yet** in the library and on open; it is never treated as damaged, backed up as unreadable or offered for repair, and opens normally when its content arrives.
  - **Check sync safety** (345): command and settings row, plus a notice at startup when new problems are found and on opening a notebook: notebooks folder inside `.obsidian` or a hidden or `.nosync` folder, names OneDrive, Windows or Android storage refuse, long paths, names differing only in case, files of 10 MB / 100 MB or more, and whether files from other devices ever arrive. What cannot be detected (the sync app's own exclusions and limits) is said in the dialog and in `docs/architecture.md`.
  - Not yet verified in Obsidian or on Android hardware.
- **Resilience** (steps 135-143; no change to the document format)
  - **Safe mode** (#346): if opening a notebook crashed or froze last time, the next open uses safe mode: no low-latency ink or predicted ink, no page thumbnails, no companion note, no PDF text read ahead, and PDF and image backgrounds appear only after the ink is painted (they are skipped if the last safe open died while loading them; *Show images and PDFs* brings them back). A banner says so and offers **Open normally** and **Repair…** (the integrity report of that notebook, with *Restore a version…* and, for an unreadable file, the repair); after two failures in a row the repair is highlighted. The "opening" marker is set right before the file is read and cleared one second after the first paint; it is kept per device in Obsidian's local storage, never synced. Closing the tab or switching apps while opening is not counted. Logic in `src/storage/safe-mode.ts`.
  - **Storage full** (#347): a failing save is classified (storage full, read-only or no permission, partial write, other) and shown in a persistent **Not saved** banner with **Retry now**; saving retries by itself with a growing delay (5 s doubling up to 1 minute), and the regular timed saves wait for it instead of hammering a full disk. The document stays in memory and in the instant save journal. Every write (up to 2 million characters, every write while saving is failing) is read back; a partial file is replaced by the previous content at once, and after a full disk the file is touched again only once a space check in the plugin's folder succeeds, so a full disk never leaves a half-written notebook behind when the old one can be put back. Logic in `src/storage/write-guard.ts`; hooks in `DocumentSession`.
  - **Integrity check with checksums** (#390, extends #27): each device remembers (in its local storage) fingerprints of the last five versions it wrote of each notebook. When a notebook is opened or reloaded, a file that is exactly an older version this device wrote (a sync service put back a stale copy), or whose pages changed while its edit time did not, shows an **Unexpected change on disk** banner with **Restore a version…** (version history), **Keep this version**, and, when it replaced the version that was open, **Restore the newer version** (merged back as one undo step). Normal edits synced from another device, metadata changes from the library and version-history restores are never reported. When a reload replaces the open version with such a file or with an unreadable one, the open version is first kept as an `integrity` backup. Nothing is restored automatically. New command **Check notebooks integrity**: reads every notebook (parse, save check, the device's ledger, asset files present and of the recorded size) and lists the problems with *Open*, *Repair…*, *Restore a version…* and *Keep this version*. Logic in `src/storage/integrity.ts`; dialog and banners in `src/view/resilience.ts`.
- **Performance** (steps 156-161; no change to the document format)
  - **Level of detail for zoomed-out strokes** (roadmap 387). When the page is shown below 50 % zoom, and in thumbnails, committed strokes are filled from a simplified shape whose difference from the exact one is at most 0.5 device pixels (Douglas–Peucker; the tolerance steps 0.25, 0.5, 1 and 2 pt are chosen from the zoom and the screen's pixel ratio), cached per stroke and level; at 50 % and above, and on screens dense enough that nothing would be gained, the exact geometry is drawn as before. Strokes written with perfect-freehand (render 1) have their outline flattened and simplified into a polygon; wet-ink strokes (render 2) keep fewer nodes of the same construction. Nothing is saved differently, nothing about writing (wet ink, input, how strokes look at normal zoom) changed. Measured on a PC with a 10,000-stroke notebook scrolled through at 49, 35 and 25 % zoom (`npm run bench:lod`): redraw per frame 52 → 23, 64 → 27 and 81 → 29 ms for render-1 strokes and 61 → 37, 72 → 45 and 91 → 52 ms for render-2 strokes (1x screen); not measured on Android.
  - **Heavy page warning** (roadmap 380). A page with more than 3,000 strokes, 120,000 points or 20 MB of images shows a discreet bar at the bottom of the view (never while writing) with **Split page** and **Dismiss**. Split page moves the lower half of the content (balanced by points, cut in the widest blank gap near the middle) to a new page right after it, with the size and paper of the page: strokes and text boxes keep their horizontal positions and their distances to each other and are moved up so the content starts near the top of the new page; it is one undo step. Pages that show a PDF or a scan only offer Dismiss (their ink annotates the background). Dismiss lasts until the notebook view is closed. Not yet verified on Android hardware.
- **Quick navigation** (roadmap 364, 365, 366; steps 162-169). No document format change.
  - **Go to page…** (command): a quick switcher over every notebook. Type part of a notebook name, a page number (`12` or `p12`, alone or after the name: `physics 12`), a bookmark title, a page tag or words from a text box; results are fuzzy, show a small page thumbnail (drawn lazily, one at a time, cached) and open the notebook at that page. With nothing typed it lists the pages edited last. It uses the library index (a cached copy, brought up to date by reading only changed notebooks); the index now also keeps bookmark titles, so it is rebuilt once after the update.
  - **Recently edited pages** (command, and *Recent pages* in the library sidebar): a list ordered by last edit. It comes from a small per-device log of (notebook id, page id, time), written a few seconds after real edits only (not by scrolling or opening), capped at 100 pages, stored in Obsidian's device-local storage: it is not a vault file, does not sync and is not in the notebook. The page is found by its id when you open it, so it survives reordering; a deleted page shows a notice. The page logged is the one in view when the edit was made.
  - **Go to page number…** (command, and tapping the page indicator in the toolbar, which opens the page sheet with *Go to* first): type `12`, `p12` or the start of a bookmark title.
  - Not yet verified on Android hardware.

### Changed
- The long "…" menu and the page menu are replaced by the *All actions* sheet and the page sheet; the pen side button's radial menu is the redesigned radial dial; PDF search, hide annotations, dim and margins moved to the contextual bar and the sheets.
- Commands are generated from the action registry; their ids are unchanged. Use counts are stored per device in Obsidian's local storage, never in the vault.

### Fixed
- Sync safety: an empty notebook file is no longer always "not downloaded": with evidence of damage (this device wrote the file, journal entries, our own cut-off write) the open document is kept in memory with *Write it back* and *Recover…*, the version that was open is always backed up first, and Repair is allowed after a confirmation.
- Sync safety: a file that is cut off, NUL-padded or changed seconds ago is "still arriving" instead of broken: at most one backup per content (size-capped), polling goes on, a dirty save waits instead of writing over the download, and Repair warns when the file changed in the last few minutes.
- Save read-back: only our own partial write (empty, NUL-padded or a prefix of what was written) is repaired, so a sync client writing in place is never clobbered; when another valid version replaced ours, our text is kept as a `conflict` backup before that version is loaded.
- Integrity: a version-history restore is written with a new edit time, so other devices no longer report it as a sync rollback; *Restore the newer version* is no longer the primary action for a rolled-back file.
- Presence files are refreshed every 5 minutes (and on resume only when that old) instead of every minute, which cut the uploads per open notebook.
- After a long failing save streak, a newer version saved elsewhere is backed up and offered for merge (one undo step) instead of being overwritten with the older local edits.
- Writes above 2 million characters are now read back and compared by length, start and end instead of not being verified.
- *Check notebooks integrity* reports an empty notebook as not downloaded (Repair asks first) and an empty or smaller asset file as still arriving, not as damage.
- An image that fails to decode (usually still being written by the sync app) is loaded again when its file changes.
- The quick switcher saves the notebooks it read into the library index (no re-reading every session), and neither it nor the library saves over an index written by a newer plugin version.

### Added
- **Format v7: bookmarks, outline, page tags, synced position, new papers** (manual steps 64-67)
  - **Format v7**: optional `meta.bookmarkInfo`, page `tags`, document `position` and the new paper kinds, with a v6 → v7 migration. Files saved with it open read-only (with a backup) in 0.5.x. Duplicate page, page restore, conflicted-copy merge, repair and library edits keep the new fields.
  - **Outline with coloured bookmarks** (#15, #85): the Pages panel has an outline mode listing the bookmarked pages in page order with a title, a colour and a category (*Important*, *To review* or a custom one), a category filter and a button to bookmark the page in view; tap a row to jump, its menu edits (rename, recolour, category) or deletes the bookmark. The page menu has *Edit bookmark…*. Thumbnails show the bookmark title and a star in its colour. Every change is one undo step.
  - **Page tags** (#119): page menu *Page tags…* (with the tags already used in the notebook as chips); the Pages panel filters by tag; the library search finds page tags and opens the notebook at the tagged page.
  - **Last position shared across devices** (#125): the notebook stores the page and height where it was last read, so another device opens it there. It is written only together with a content save (never on its own, so reading or scrolling does not touch the file and two devices that only read never fight). A link or search hit still opens its page; a restored workspace keeps this device's page unless another device was in the notebook later; *Continue last notebook* keeps this device's page.
  - **More papers** (#73): Cornell, music staff, isometric, hexagonal, calligraphy (slanted guides), daily planner and weekly planner (2 × 4 boxes, 4 × 2 in landscape), in the new-notebook dialog, the default-paper setting, the page menu, thumbnails and PDF/SVG export. Fine lines fade out when zoomed out as on the other papers.
- **Gestures** (manual steps 68-73)
  - **Finger taps** (roadmap 3): a tap with two fingers undoes, with three fingers redoes (setting *Finger taps*: two undo / three redo, swapped, or off; on by default). A tap needs all fingers to land within 150 ms, move at most 12 px, lift within 150 ms and finish within 350 ms, so panning and pinching never trigger it; touches while the pen is near (palm rejection time), palm-sized or edge-zone contacts, and a pen touching in the middle spoil it. The few pixels the view may have moved are put back, and a tap leaves no ink. A finger that lands among fingers that are already panning or pinching no longer starts a stroke (also with *Draw with finger*).
  - **Scribble to erase** (roadmap 4, setting, off by default): a fast back-and-forth scratch with the pen over existing ink deletes the strokes it crosses; the scribble is not kept and the whole thing is one undo step. Detector in `src/ink/scribble.ts`: at least four direction reversals between legs of 12 pt or more, roughly parallel, mostly piled up instead of travelling along a line (so "mmm" and sweeping zig-zag shading do not count), under 300 ms per leg on average; a stroke is deleted when at least two different legs cross it, and very large strokes (rulings, frames) are left alone. Off by default because a false positive deletes ink.
  - **Auto-scroll while writing** (roadmap 36, setting, off by default): when a stroke ends in the bottom 18 % of the view, the page scrolls up smoothly (320 ms, ease-out) after a 700 ms pause so the tip sits at 40 % of the height. It never moves while a pen or finger is down; a touch cancels it; it stops at the end of the document.
  - **Pen side button** (roadmap 2): the setting *Pen side button* gains *Lasso while held* and *Previous tool while held* (the tool used before the current one; the current tool if there is none). The tool is chosen when the pen touches down. These options are part of the unified side-button setting of 0.5.2 (key `penSideButton`, default *Radial menu on click, erase while held*); the earlier development key `penButtonAction` is migrated (`lasso` stays, `lastTool` becomes `previous`). A selection made with the lasso option stays after the button is released and is cleared when you write.
- **PDF reading** (manual steps 74-78)
  - **Search the PDF text** (#44): command *Search PDF text* and an entry in the toolbar's "…" menu open a search bar over the page. Matches ignore case, accents and ligatures ("caffe" finds "caffè"); at least 2 characters. Results are listed with their notebook page and the words around them, every match is marked on the page (yellow, the current one orange; a transient overlay that is never saved), and next/previous (also the commands *Next/Previous PDF search result*, Enter and Shift+Enter) scroll to it. The text of each PDF page is read once and cached; the search starts at the page in view, handles four pages at a time and gives the screen back every few milliseconds, so typing, scrolling and writing stay responsive on a big PDF, and a new query cancels the old one. At most 500 matches are listed. Marks inside a long line use the character widths of the PDF's font as the WebView measures them.
  - **Highlighter that snaps to the text lines** (#43): the highlighter's options have *Snap to text lines* (off by default). When on, a highlighter stroke over PDF text is replaced at pen-up by straight highlighter strokes, one per line of text it crossed, covering the words it covers (a word counts when at least 40% of it is under the stroke) and as high as the line. They are ordinary highlighter strokes (vector, page coordinates) in the same undo step; a stroke that is not near any text, or made before the page's text was read, stays as drawn. Rotated text is not snapped.
  - **Show or hide all annotations** (#188): command *Show or hide annotations on PDF pages* and a "…" menu entry hide the ink and text boxes on PDF pages (other pages keep theirs) to reread the clean PDF. View only: nothing is saved or changed, editing and the toolbar are off while hidden (a finger still scrolls and zooms), and a banner says so and has the button that shows everything again. Exports, thumbnails and embeds still contain the annotations.
  - **Dim the background** (#199): command *Dim PDF and image backgrounds* and a "…" menu entry with a strength slider (10-80%) draw PDF and image backgrounds lighter so the ink stands out. Kept in the plugin settings (`dimBackground`, `dimStrength`), per device. Exports, thumbnails and embeds are not dimmed (they show the notebook, not one reader's screen); there is no export option for it yet.
- **Navigation and huge notebooks** (manual steps 79-81)
  - **One page at a time** (#14): setting *Scrolling* (*Continuous (vertical)* or *One page at a time*), a toggle *One page at a time* in the toolbar "…" menu and the command *Toggle one page at a time*. In that mode the pages sit side by side and each one is fitted to the view width; a sideways finger swipe (one or two fingers, or a trackpad / Shift+wheel) drags the page along and turns to the next or previous one when it went past about a fifth of the width or was flicked, then the page snaps into place with a short animation (none with reduced motion). A vertical drag scrolls inside a tall page; zoomed in, you pan inside the page and a long push past its edge turns it. Pinch zoom still works. The pen never turns the page (it draws), and the fling after a swipe does not move the page. *Next page* / *Previous page* (commands) animate; the page panel jumps. No change to the file format, the writing pipeline or the ink.
  - **Reopen where you left off** (O16): the workspace state now also keeps the zoom and the scroll position (relative to the fit-to-width zoom and to the page, so they survive rotation or a different pane size), and *Continue last notebook* restores them too (stored in the plugin settings, written at most every few seconds when only the position changed). Nothing is written into the notebook file. A link to a page (`#p3`) still opens that page fitted.
  - **Progressive loading of large notebooks** (#329): a notebook over about 2 MB opens with the page you want shown first, read-only, while the other pages are read and validated in short slices (about 10 ms, nearest pages first) that leave input and painting free. Editing and saving start only when every page has been read and has passed the same validation as before; if a page turns out to be damaged the notebook is treated as an unreadable file (backup, never overwritten). Notebooks with edits in the instant-save journal are loaded in full first, as before. On a PC (`npm run bench:open`, headless Chrome, in-memory vault, not Android): 10,000 strokes on 10 pages, first painted page 207 ms → 150 ms; 100,000 strokes on 100 pages, 1771 ms → 1019 ms. Time until the notebook is complete and editable is about the same or a little longer (10,000: 145 ms plus the paint → 221 ms; 100,000: 1702 ms → 1922 ms) because the first paint now happens inside that window.
- **Library trash, page trash and templates** (manual steps 82-91)
  - **Library trash** (#160): deleting a notebook or a folder (now also a non-empty one) from the library moves it to `<notebooks folder>/_trash/` and remembers its original path. *Trash* in the library sidebar lists the items; *Restore* puts an item back where it was, or under `Name 2` if the name is taken; *Delete permanently* and *Empty trash* ask first (permanent deletion follows Obsidian's *Deleted files* setting). New setting *Empty the trash automatically* (days, default off). The trash is invisible to the library, search, companion notes and conflicted-copy detection; assets are never deleted, so those used only by trashed notebooks stay.
  - **Page trash** (#26): *Delete page* keeps the page as its own file `_trash/pages/<notebook id>/<entry id>.json`, written once and never rewritten (not in the notebook format; assets by id). Page menu *Deleted pages...* lists them with thumbnails and restores one after the page that preceded it as one undo step. At most 50 pages per notebook, 30 days.
  - **Page templates** (#74): page menu *Save page as template...* (content, paper, size, background) stores a small notebook file in the templates folder (setting *Templates folder*, default `_templates` in the notebooks folder); *New page from template...* and a *Template* row in the *New notebook* dialog open a gallery with thumbnails, including built-in Cornell, meeting notes and to-do templates.
- **Lecture pack and exercise page** (manual steps 92-99; no change to the document format or to the writing engine (sampling, wet ink, geometry, stabilizer))

## 0.5.2 — 2026-10-30

Hotfix for 0.5.1. Not verified on Android hardware (see `docs/testing.md`). What the S Pen really sends was observed by the user on a Samsung tablet with the Pen button test and Chrome's pen-tracker page; the chorded press during contact (item 3 of *Fixed*) is a hypothesis from one observation and may not hold.

### Fixed
- **The radial menu could not be reached on a Samsung tablet.** With Air command off, the Pen button test saw no event at all when the S Pen side button was pressed *on the page it was tested in*, while Chrome on the same tablet shows the button as a primary press with zero pressure. The menu is now reachable in four ways:
  1. **Side button pressed while the pen hovers** (Samsung / Chromium): `pointerdown` with `button 0`, `buttons 1` and `pressure` exactly 0 (a real nib contact has pressure above 0), also `buttons` going 0 to 1 in a pen `pointermove` / `pointerrawupdate` with pressure 0. It only counts for a pointer that was hovering just before (`buttons 0` seen for the same `pointerId`), never draws and never erases from the pressure-0 phase, and can be switched off (*A zero-pressure press is the side button*). Press the button *before* touching the page: pressed after the nib is down, `buttons` is already 1 and it cannot be told apart.
  2. **Hold the pen still** on the page (see *Changed*).
  3. **Side button pressed while the nib touches** (experimental, setting *Side button pressed while writing*): a dispatched pen `pointermove` / `pointerrawupdate` with `button 0` (instead of -1) while `buttons` stays 1 finishes the stroke so far (kept, never discarded) and the contact then acts as the button's tool until the next such event or the lift. Never from `pointerdown`, never from coalesced or predicted events, only after an ordinary move was seen in the contact, not within 40 ms of the landing, debounced 120 ms; a device whose moves all carry `button 0` never triggers it.
  4. **Finger long-press** (see *Added*).
- The side-button signals that other devices may deliver (`buttons & 2`, `contextmenu`, `auxclick`, a mouse right button after pen activity) are kept.
- Honest texts (English and Italian): the *Pen side button* setting says the button works on Samsung only with the pen hovering, that it may never reach Obsidian on some devices, and names the two alternatives; the Pen button test shows *No side-button signal received yet on this device* until one arrives.

### Changed
- **Pen side button** default is now **Radial menu on click, erase while held**: with the pen hovering, press and release the button to open the menu on the release (at the pen position); press the button and then touch the page to erase (current eraser mode, size and filter) for as long as the contact lasts in that button session; no menu then. New options: *Lasso while held* and *Previous tool while held* (the others: radial menu only, erase while held, nothing). The setting is stored under a new key (`penSideButton`): the 0.5.x default "radial" is not carried over, an explicit "erase while held" or "nothing" is.
- **Open the radial menu by holding the pen still** is more robust and **on by default only while the device has never delivered a side-button signal** (the app remembers the first signal in the settings: `penButtonSeen`). Once one has arrived the default is off; an explicit choice always wins. The pen must be still from the very first contact: 700 ms (was 600 ms) within 6 px of where it landed. Once the stroke has moved it can never open the menu, however long it then rests, so dots, slow strokes and pauses in a stroke are safe. The discarded stroke leaves no dot and nothing for undo, and the pen is not left "down" for palm rejection afterwards. Never for the eraser end; needs the side button action to open the radial menu.
- The Pen button test shows the event type and the pointer id on every line, labels the pressure-0 press (*side button (pressure 0 primary press)*), the touch while it is held, the lift and the release (with *click: opens the menu*), and `pointermove` with `button 0` during contact as *possible side button*. A pressure-0 press counts as a side-button signal and turns the hold-still default off.

### Added
- **Finger long-press opens the radial menu** at the finger (setting *Open the radial menu with a finger long-press*, on by default): a finger still for 500 ms within 10 px, only while finger drawing is off (pen-only), only a single finger, and not when the palm-rejection window says a pen is near. The ring opens beside the finger, not under it, so the fingertip does not cover the sectors. A pan, a pinch or a two-finger tap that starts before 500 ms is not affected.

## 0.4.1 — 2026-10-29

Hotfix for 0.4.0. Not yet verified on Android hardware.

### Fixed
- **Black page, nothing could be written** (reported on a Samsung tablet with S Pen, dark theme): the page area stayed empty — black in the dark theme — and no tool drew, while the toolbar and the page panel worked. Cause: two merges in the 0.4.0 cycle damaged `styles.css` (the "view wave 2" and "integration P1" sections lost their closing braces and many declarations). Browsers with CSS nesting read the rest of the file as nested rules that never match, so the page container was no longer a flex box: the drawing area had zero height, the canvases were never sized and no pointer event reached them. The two sections are restored from their original commits (embed previews and the page panel's hidden/narrow states were affected too).
- One bad stroke, image, PDF background or text box can no longer stop the page from being drawn: every part of a frame is drawn in its own guard, a failure is skipped and logged once in the console (`[notebook] render …`). If painting wet ink fails, the stroke being written is shown on the regular live layer instead, so the pen always leaves ink. Pointer events are guarded the same way (`[notebook] input …`) and a stroke is always closed when the pen lifts.
- Insert image and Insert image page: HEIF/HEIC photos get the same clear message instead of a generic failure (and are not copied into the vault); sizes are read through the scanner's decoder with its fallbacks.
- Scanner: photos in HEIF/HEIC (Samsung "High efficiency pictures") get a clear message instead of "Could not read this photo"; robust decoding (fallbacks, safe canvas sizes for 12-50 MP photos); in-app camera that always yields JPEG.

### Changed
- New setting **Low-latency ink (experimental)**, **off by default**: the pen's wet-ink canvas asks for a low-latency (`desynchronized`) context and `pointerrawupdate` is listened to only when it is on. On some Android GPUs a low-latency canvas is composited as an opaque layer; off, ink is still painted as each pen event arrives, on a regular canvas, with `pointermove` and coalesced samples. If the low-latency context cannot be created, a regular one is used.

### Development
- Browser harness (`dev/harness/`, `npm run harness`, `npm run harness:check`): the real notebook view on a stand-in for the `obsidian` module, checked headlessly in Chrome on old (v3) and new notebooks, light and dark theme, tablet, phone and desktop viewports with their pixel ratios, synthetic pen input and injected faults, with screenshots and composited-pixel checks. See `docs/testing.md`.
- Unit tests guard `styles.css` (balanced braces, no accidental nesting, the layout declarations) and the new guards and setting.

Into the notebook as pages (**Scan into this notebook**, page menu), as an image (**Insert scan as image**), or as a new notebook (**New notebook from scan**).
- **Assets**: PDFs and images are stored once in `<notebooks folder>/_assets/`, named by the hash of their content, and referenced from the notebook.
- **Page navigator** (Pages panel): thumbnails, tap to jump, drag to reorder, bookmarks and a bookmarks-only filter.
- **Tools**: shapes (line, arrow, rectangle, ellipse) with hold-still recognition of rough lines, rectangles, ellipses and arrows; text boxes; images; ruler placed with two fingers (the pen follows its edge); lasso now selects text boxes and images too; **infinite page** (grows downwards when you write near the bottom).

- **Writing engine** (wet ink): the stroke being written is painted as each pen sample arrives (`pointerrawupdate` where available, `pointermove` otherwise), only the new part, on its own low-latency canvas. New strokes use a geometry (disc chain on a smooth curve) that is identical while writing and after the pen lifts, so the line no longer jumps at pen-up. The highlighter looks the same while writing and after.
- Export: PDF backgrounds and images are rasterised as JPEG (PDF pages at 200 dpi) and embedded in PDF and SVG exports.
- Settings: *Version history interval*, *Versions to keep*, *Predicted ink*. Commands: **Open library**, **Import PDF as notebook**, **Scan into this notebook**, **New notebook from scan**, **Insert notebook embed**, **Restore a previous version**.
- Italian translation of the new UI.

### Changed
- **File format v4 and v5.** v4 adds notebook `meta`, `assets`, page backgrounds (PDF page or image), text and image elements, infinite pages and the `shape` tool. v5 adds the per-stroke `render` field (1 = the old perfect-freehand look, kept for every existing stroke; 2 = the new ink engine). v3 and v4 files migrate in memory and are rewritten as v5 on the first edit. **Files written by 0.4.0 open read-only in older versions** (with a backup copy).
- Stabilization is an adaptive filter (1€ filter): less jitter at rest and much less lag while writing at the same level (default 2).
- Pressure, real or simulated, is decided at the start of each stroke and never switches in the middle of it.
- *Predicted points* is replaced by *Predicted ink*, **off by default** (predicted samples overshoot at turns and at the end of a stroke).
- Saves, journal entries and thumbnail refreshes wait while the pen writes (and 350 ms after), never longer than a few seconds.
- The notebook container is isolated in one module (`src/storage/format.ts`), so a later move to Markdown (M4) is a contained change.
- Duplicating a notebook gives it a new document id.

### Fixed
- Safety: during continuous writing the journal entry now lands in the first short pen-up gap (120 ms) or after at most 1 s / 1.5 s, instead of up to 4 s / 8 s later; the journal no longer writes while a save of the same revision is in flight (a crash could otherwise turn a "merged" entry into a stale one); a partial erase of a fast curved stroke keeps the curve (inserted points follow the ink geometry, not the chord).
Found by independent reviews of the new data-safety code:
- The journal is keyed per file identity and per session, so two notebooks or two sessions cannot replay each other's entries; an entry that does not match the file on disk is never applied, a copy goes to the backup folder first.
- Recovery works again after a notebook was unreadable and then became readable.
- Assets are verified before a page refers to them.
- Duplicate page ids are rejected on read and on write.
- Restoring a version aborts if the save of the open notebook fails, or if the version belongs to a different notebook.
